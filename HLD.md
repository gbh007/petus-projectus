# Petus-projectus

## Данные на схеме

- `Desktop client` - нативное приложение
- `JSON proxy` - микросервис прокси
- `gRPC Gate` - микросервис для работы со внешними клиентами
- `Auth service` - микросервис для работы с аутентификацией/авторизацией
- `Log service` - микросервис для работы с активностью
- `Notification service` - микросервис для работы с уведомлениями
- `Kafka` - основной контроллер событий
- `Event handler` - обработчик событий
- `ClickHouse` - основная БД для OLAP
- `RabbitMQ` - основной контроллер очереди задач
- `Worker` - микросервис для исполнения задачи
- `MariaDB` - основная БД для OLTP
- `Prometheus` - сборщик метрик
- `Redis` - хранилище кеша сессий пользователя

### Запустить задачу

1. Пользователь вводит данные в `Desktop client`
   - Время на выполнение задачи
     - От 1 до 60 секунд
   - Вероятность неуспешного завершения задачи
     - От 0 до 100, где 100 это гарантированное неуспешное завершение
2. Отправляется запрос в `gRPC Gate`
3. Проверяем авторизацию, выясняем ID пользователя в `Auth service`
4. Отправляем событие в `Kafka` с данными:
   - ID пользователя
   - Время запроса
   - IP адрес запроса
   - Тип запроса - `Task`
   - Время на выполнение задачи
   - Вероятность неуспешного завершения задачи

## Технические процессы

- Обработка события
- Обработка задачи

### Обработка события

Выполняется `Event handler`

1. Берется событие из `Kafka`
2. В `Log service` отправляются данные:
   - ID пользователя
   - Время запроса
   - IP адрес запроса
   - Тип запроса
3. Если тип запроса `Task`, то в `RabbitMQ` отправляется задача с параметрами:
   - ID пользователя
   - Время на выполнение задачи
   - Вероятность неуспешного завершения задачи

### Обработка задачи

Выполняется `Worker`

1. Берется задача из `RabbitMQ`
2. Выполняется ее обработка
   - Задача "выполняется" в течении указанного времени
     - Ко времени применяется модификатор `+-40%`
       - Генерится рандомно
     - Имитация выполнения через `time.Sleep`
   - Определяется успешность задачи через рандомную генерацию и сравнение с указанным шансом
3. Результат выполнения фиксируется в `ClickHouse`
4. Отправляется уведомление пользователю о завершении в `Notification service`
   - Фактическое время выполнения
   - Результат (успешность)
